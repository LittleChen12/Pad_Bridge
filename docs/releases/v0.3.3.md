# PadBridge 0.3.3

修复 Windows 普通启动时修改画面设置的权限错误，增加最高 120 FPS 和强制目标帧率。

## Windows 设置权限

- 旧版以管理员启动时，Python 的 `mkdir(mode=0700)` 会创建仅目录所有者、管理员和
  SYSTEM 可写的目录；所有者可能是 Administrators，导致同一个账户普通启动后无法保存。
- 新目录继承个人 AppData 权限；旧目录只给原登录用户补充访问权限，不清空连接或画面设置。
  旧配置无法访问时，启动会请求一次 Windows 管理员确认。日常运行不要求管理员权限。
- “安装扩展组件”只提升短时维护进程，界面和串流进程保持普通权限。

## 120 FPS

- Windows 画面设置支持 15～120 FPS，默认仍为 60。USB 与 Wi-Fi 共用此设置。
- 默认遵守接收端声明。勾选“强制目标帧率”后，即使 OpenDisplay 上报 60，也会按所选
  120 FPS 配置采集节奏、编码器时间基准与协议；尺寸和解码像素吞吐限制仍然保留。
- 自建虚拟副屏提供横竖屏的 60/90/120 Hz 模式。根据实际发送目标选择刷新率，不修改
  电脑主屏或用户已经启用的副屏。更新旧配置时保留自定义尺寸、GPU 与其他选项。
- 状态卡显示实际发送 FPS；强制模式同时显示接收端声明，避免把发送帧率当作物理显示帧率。
- 命令行示例：`PadBridge.exe start --transport usb --display-mode extend --monitor auto --fps 120 --force-fps`。

120 是发送目标，不保证所有设备、分辨率和网络下恒定达到。屏幕实际刷新率由 iPad 决定。
Ubuntu 图形界面的范围保持 15～60 FPS，强制模式仅用于 Windows。

## 验证

- Windows 单元、协议和界面测试，覆盖普通权限设置迁移、120 FPS 协商与强制发送、编码解码、
  副屏刷新率及原布局保留。
- 实机使用普通用户令牌保存 120 FPS 设置；通过 WGC + NVENC 测试原生副屏 120 Hz、
  断线重连和副屏回收。
- 当前测试 iPad 上报 60 FPS，USB 强制模式已收到超过 60 的接收统计；这不代表屏幕物理
  刷新率为 120 Hz，也不承诺 Wi-Fi 稳定 120 FPS。

下载 Windows 用户安装包 `padbridge-0.3.3-windows-x64-setup.exe` 即可升级，沿用已有设置。
