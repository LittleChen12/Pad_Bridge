# PadBridge 0.3.0

新增 Windows 11 x64 原生后端：主屏镜像、自动虚拟扩展屏、已有副屏选择、Windows Graphics Capture / GDI 光标采集、
低延迟 NVENC/x264 编码、USB/Bonjour Wi-Fi 传输、触控、后台进程、托盘界面、便携包及 Windows CI。
Qt 界面延续 Ubuntu 的左侧导航、三页布局、卡片与紫色配色；连接错误保留在状态卡中。
连接页选择“扩展屏幕”后直接自动管理 iPad 副屏，移除重复的屏幕来源选择器和刷新按钮；已有副屏仍可通过命令行选择。
扩展模式新增“副屏位置”左侧/右侧选择并保存，新连接按所选方向放置；连接期间保留手动排列的位置。

Windows 默认使用镜像。首次扩展通过界面安装固定版本的签名 Virtual Display Driver；
连接时匹配 iPad 尺寸，断开和掉线时停用本程序的虚拟显示设备，使其从系统显示列表消失，
重连时重新创建。安装时配置固定启停任务，普通权限运行也无需反复提权。保留原有主屏及其他显示路径。
NVENC 使用逐步帧内刷新，避免单帧码率缓冲下每两秒完整关键帧带来的清晰度跳动；
仍保留无 B 帧、无前瞻、立即出帧及接收端主动请求 IDR 恢复。
Windows NVENC 直接接收 BGRA，减少 CPU 复制和颜色转换；有界发送线程让网络等待与画面处理并行。
镜像与扩展比例变化时自动同步 iPad 视频会话，修复必须再次手动重连才能去掉黑边的问题，
同步期间保留副屏和窗口位置。帧率统计改为最近两秒，避免启动过程拉低整段平均值。
USB 镜像/扩展和 Wi-Fi 原生扩展已在真实 iPad 上运行；更多硬件与弱信号场景需继续验收。
详见 [Windows 使用说明](../windows.md)。

Ubuntu/Xorg 保留 GTK、GStreamer 和 systemd，增加 CUDA 转色/缩放与 NVENC 组合自检、
两帧在途限制、独立顺序发送线程、滚动 FPS 与阶段耗时统计。GPU 路径不可用时保留 CPU/NVENC 和 x264 回退。
左右副屏默认位置、持久显示的连接错误和实际 FPS 同步到 GTK 界面。
共享分辨率计算移至独立视频模块，设置文件使用 UTF-8。Linux 会话扩展保留在上游补丁中。
Ubuntu 24.04 的 GStreamer 1.24 不支持 Windows 使用的逐步帧内刷新参数，Linux 未声称支持此项。

### USB 帧率诊断补充

发送状态补充各阶段 P95 耗时和最近两秒最长帧间隔。静止画面仍按目标帧率发送；
NVIDIA 笔记本显卡降频可能让编码超过每帧预算，Windows 指南新增 PadBridge 专用电源管理设置的排查与撤销方法。

虚拟屏断线重建后重新枚举图形输出，修复采集库缓存旧显示器标识而退回 GDI、导致帧率明显下降的问题。

完整的实现说明、USB/Wi-Fi 实测结果与限制见 [Windows 优化记录](../windows-optimization.md)。
USB 在本机原生尺寸短测接近 60 FPS，依赖相应应用专用的显卡电源设置；Wi-Fi 仍有延迟尖峰，
当前自动码率是按连接方式选择固定值，尚未实现网络自适应。
Linux 本轮实现、实测与平台差异见 [Linux 优化记录](../linux-optimization.md)。
