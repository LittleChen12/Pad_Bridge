# PadBridge 0.3.0

本版将 Windows 11 后端与 Linux 性能优化合入同一个正式版本，支持通过 USB 或同局域网 Wi-Fi
把 iPad 用作镜像屏或扩展屏。iPad 端仍使用 OpenDisplay。

## 下载与升级

| 文件 | 用途 |
| --- | --- |
| `padbridge_0.3.0_amd64.deb` | Ubuntu 24.04 x86_64 / Xorg 安装包 |
| `padbridge-0.3.0-windows-x64.zip` | Windows 11 x64 便携包，完整解压后运行 `PadBridge/PadBridge.exe` |
| `padbridge-0.3.0-source.tar.gz` | 与本次版本标签对应的完整源码 |
| `SHA256SUMS`、`SHA256SUMS-windows` | Linux/源码及 Windows 包的校验值 |

升级前从托盘退出旧版。Ubuntu 使用 `sudo apt install ./padbridge_0.3.0_amd64.deb`；
Windows 将便携包完整解压到新目录。用户设置保存在各自的用户配置目录中。

## Windows 11

- 新增原生镜像与自动虚拟扩展屏、USB/Wi-Fi、触控、Qt 界面和托盘。
- 首次扩展安装固定版本的签名虚拟显示组件，之后自动创建和回收本程序的副屏。
- WGC 采集、NVENC 直接处理 BGRA、独立发送线程，保留 GDI/x264 回退。
- 无 B 帧/前瞻、四帧码率缓冲及逐步帧内刷新，保留主动请求 IDR 恢复。
- 修复镜像/扩展切换后残留黑边，以及副屏重建后误用旧采集设备的问题。

安装与依赖见 [Windows 使用说明](https://github.com/LittleChen12/Pad_Bridge/blob/v0.3.0/docs/windows.md)。

## Ubuntu 24.04 / Xorg

- 新增 CUDA 转色/缩放和 NVENC 组合自检，保留 CPU 转色/NVENC 及 x264 回退。
- 限制两帧在途，独立顺序发送，让网络等待与编码并行，避免阻塞桌面事件循环。
- 左/右副屏位置选择与旋转布局恢复；退出和后台异常结束后只回收拥有的副屏。
- 保留镜像不修改主屏、XShm 尺寸变化保护，以及首帧后自动同步 iPad 显示区域。
- 同条件 USB 短测中，串流进程 CPU 从约单核 42% 降至 17%，发送帧率仍约 59.7 FPS。

实现、测量口径和数据见 [Linux 优化记录](https://github.com/LittleChen12/Pad_Bridge/blob/v0.3.0/docs/linux-optimization.md)。

## 两端共通的体验

保存分辨率、帧率、码率与默认左右位置；状态数据提供最近两秒实际 FPS、各阶段耗时与接收端统计。
连接错误保留在状态卡中。关闭窗口隐藏到托盘，真正退出会停止串流并收回副屏。
未连接时不运行采集或编码，连接后静止画面仍保持持续采集。

## 验证与范围

- Linux 183 项单元/协议测试通过；Ubuntu 与 Windows CI 均执行测试、构建和包检查。
- Linux 实机验证 USB/Wi-Fi、镜像/扩展、左右位置、回收、托盘退出与闲置占用；
  用户确认新版无线画面和 iPad 横竖旋转正常。Windows 实机验证详见
  [Windows 优化记录](https://github.com/LittleChen12/Pad_Bridge/blob/v0.3.0/docs/windows-optimization.md)。
- Linux 扩展仍需支持的空闲 Intel/AMD HDMI 接口；镜像请在 PadBridge 内切换。
  Windows USB 需要 Apple 移动设备支持，首次虚拟扩展需要安装驱动组件。
- Wi-Fi 仍可能出现延迟尖峰；自动码率是 USB 24 / Wi-Fi 10 Mbps 固定预设，尚无动态码率。
  Linux 的 GStreamer 1.24 没有 Windows 使用的逐步帧内刷新参数。
- 当前目标为 Ubuntu 24.04 amd64 / Xorg 与 Windows 11 x64；其他系统和硬件尚未全面验证。
